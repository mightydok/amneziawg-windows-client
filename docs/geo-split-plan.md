# План доработки: гео-раздельный роутинг для AmneziaWG Windows client

Ветка: `feat/geo-split-routing` (от `master` @ `800416d`, 2026-08-29). Редакция 2 (2026-09-05): выбрана схема маршрутов-исключений, lockdown убран, добавлена политика снижения числа маршрутов по замерам.

## 0. Что дано

Клиент состоит из двух репозиториев:

| Репозиторий | Что внутри | Где менять |
|---|---|---|
| `amneziawg-windows-client` (форк `mightydok`, локально `awg-client/`) | UI (`ui/`, walk), менеджер-сервис (`manager/`), апдейтер (`updater/`), инсталлятор | UI, настройки, IPC, скачивание и подготовка списка |
| `amneziawg-windows` (форк `mightydok`, локально `awg-lib/`, пин v3.1.20260814 = `e90531d`) | `conf/` (парсер .conf), `tunnel/` (сервис туннеля, маршруты, `firewall/` = WFP kill-switch) | маршруты, WFP-исключения, ключ конфига |

В `go.mod` клиента на время разработки `replace github.com/amnezia-vpn/amneziawg-windows/v3 => ../awg-lib`, в релизе `=> github.com/mightydok/amneziawg-windows/v3 <commit>`.

Как сейчас работает kill-switch (`awg-lib/tunnel/addressconfig.go:177`, `docs/netquirk.md`): если у туннеля один peer и в `AllowedIPs` есть `0.0.0.0/0` или `::/0`, сервис туннеля открывает динамическую WFP-сессию (`tunnel/firewall/blocker.go:104`) и ставит фильтры: permit процессу туннеля, loopback, TUN-интерфейсу, DHCP/NDP, DNS только к серверам из конфига, **block всё остальное** (`rules.go:900`). Фильтры живут, пока жив процесс `amneziawg.exe /tunnelservice`.

Маршруты: `configureInterface()` (`addressconfig.go:60`) превращает каждый `AllowedIPs` в маршрут на wintun с next-hop 0 и вызывает `luid.SetRoutesForFamily()` (`winipcfg/luid.go:247`), по одному `CreateIpForwardEntry2` на префикс.

Сокет туннеля привязывается к физическому интерфейсу через `IP_UNICAST_IF` (`defaultroutemonitor.go:20`), поэтому UDP до endpoint не зависит от таблицы маршрутов.

## 1. Механизм «RU напрямую, остальное через VPN»

### 1.1. Выбор схемы по замерам

Замер на списке ipverse от 2026-09-04 (скрипт в scratchpad `geocalc`, воспроизводится из `geolist` в фазе 1):

| Что считаем | IPv4 | IPv6 |
|---|---|---|
| RU-префиксов в списке (без потерь, уже агрегировано) | 8 649 (45,2 M адресов) | 2 179 |
| Дополнение до `/0` (маршруты в схеме «AllowedIPs = не-RU») | **21 683** | **13 439** |
| Дополнение при склейке зазоров ≤ 65 536 адресов | 4 971, но в «напрямую» попадает 70 M чужих адресов | |

Вывод: схема «дополнение в AllowedIPs» отпадает, дополнение в 2,5–6 раз больше самого списка, а склейка зазоров тащит в прямой маршрут больше чужих адресов, чем есть российских.

Выбрана **схема маршрутов-исключений**:

- в `.conf` остаётся `AllowedIPs = 0.0.0.0/0, ::/0`, cryptokey routing и штатный kill-switch не трогаем;
- на wintun как и сейчас ставится `/0`;
- сервис туннеля дополнительно ставит маршруты RU-префиксов **на физический интерфейс через его текущий шлюз**. Они специфичнее `/0` и выигрывают;
- в WFP добавляются permit на те же префиксы (раздел 1.2).

Что при этом важно: маршруты привязаны к физическому интерфейсу и его шлюзу, при роуминге их надо переставить (раздел 1.7). Пока не переставили, RU-трафик уходит в туннель, это безопасная сторона ошибки.

### 1.2. WFP-исключения

Kill-switch блокирует всё вне TUN, значит прямой трафик надо явно разрешить. Новая функция `firewall.PermitRemotePrefixes(session, baseObjects, weight, prefixes)` по образцу `permitTunInterface()` (`rules.go:30`):

- слои `ALE_AUTH_CONNECT_V4/V6` (исходящие соединения; ответы на них WFP пропускает по flow), `RECV_ACCEPT` не открываем;
- условие `FWPM_CONDITION_IP_REMOTE_ADDRESS`, тип `FWP_V4_ADDR_MASK` / `FWP_V6_ADDR_MASK`; несколько условий по одному полю объединяются как OR, пакуем по 256 префиксов в фильтр: ~25 фильтров v4 + ~9 v6;
- вес 12 (как у TUN и DHCP);
- вызывается из `EnableFirewall()` внутри той же транзакции. Список должен быть подготовлен **до** `enableFirewall` (`service.go:185`), то есть сразу после `conf.LoadFromPath` (`service.go:112`), потому что дальше идёт `DropAllPrivileges`.

Отдельный permit **на приватные диапазоны** (`10/8, 172.16/12, 192.168/16, 100.64/10, 169.254/16, fe80::/10, fc00::/7`), только исходящие, вес 15, то есть выше DNS-deny (`blockDNS`, deny = 14), чтобы работал корпоративный DNS на сером адресе. Это закрывает OpenVPN и локальную сеть, см. 1.6.

### 1.3. Снижение числа маршрутов

Список ipverse уже агрегирован без потерь: 8 649 CIDR это минимум для 7 396 непрерывных диапазонов. Склейка зазоров почти ничего не даёт (зазор ≤ 256 адресов: 8 649 → 8 474). Единственный рычаг с понятной ценой это **малые российские блоки отправлять через VPN** (сторона ошибки: сайт из мелкой сети видит зарубежный IP):

| Порог «напрямую только блоки ≥» | Маршрутов v4 | RU-адресов через VPN | Доля RU |
|---|---|---|---|
| /24 (всё) | 8 649 | 0 | 0 % |
| /23 | 7 287 | 0,35 M | 0,8 % |
| **/22 (умолчание)** | **6 314** | **0,79 M** | **1,8 %** |
| /21 | 3 963 | 3,06 M | 6,8 % |
| /20 | 2 662 | 5,27 M | 11,7 % |
| /19 | 1 744 | 8,34 M | 18,4 % |

IPv6: 2 179 маршрутов, мелких блоков там нет (в основном /32…/29), резать нечего. Опция «IPv6 только через VPN» даёт 0 маршрутов v6, для российских условий это часто и есть реальность.

Конвейер в пакете `geolist`:

```
скачать → проверить → Normalize (маска, сортировка, дедуп, вложенные)
       → Policy (min-prefix, IPv6-режим, списки исключений) → набор маршрутов + набор WFP-условий
```

Кэш хранит сырой список, набор маршрутов считается при старте туннеля (миллисекунды). В UI порог выбирается ползунком с живым пересчётом «маршрутов: N, через VPN: M адресов».

Списки исключений (глобальные): `always_direct` (публичные префиксы, которые нужны напрямую независимо от размера, например конкретный банк) и `always_tunnel` (российские префиксы, которые надо гнать через VPN, например GGC-кэш провайдера, если понадобится).

### 1.4. Ключ конфига

Per-tunnel в `.conf` только включатель, остальное глобально в `settings.json` (раздел 2.2):

```
[Interface]
GeoSplit = ru
```

Правки: `conf/config.go` (поле `GeoSplit string`), `conf/parser.go:445` (кейс), `conf/writer.go` (`ToWgQuick`, чтобы редактор не терял ключ), `ui/syntax/highlighter.go:133` (`isValidKey`). В UAPI ключ не попадает. Пишется только когда режим включён, `.conf` остаётся совместимым с другими клиентами.

### 1.5. DNS

Kill-switch пропускает порт 53 только к серверам из `DNS =` и, после 1.2, к серым адресам. Куда пойдёт запрос, решает адрес сервера: `1.1.1.1` уедет через VPN, `77.88.8.8` попадёт под RU-маршрут и уйдёт напрямую. Раздельного DNS по доменам нет, документируем в `netquirk.md`.

### 1.6. Корпоративный OpenVPN и серые адреса

Маршрутизацией здесь заниматься не нужно: OpenVPN при подключении сам ставит маршруты своих серых подсетей на свой адаптер, они специфичнее нашего `/0` на wintun и выигрывают. Домашняя сеть аналогично: on-link маршрут `/24` на Wi-Fi специфичнее `/0`. Серые адреса без более специфичного маршрута попадают в `/0` и уходят в туннель, где их отбрасывает сервер, это безвредно.

Единственное, что мешает, это kill-switch: он блокирует пакеты на любом интерфейсе, кроме wintun, включая адаптер OpenVPN. Поэтому permit на приватные диапазоны из 1.2 обязателен, отдельных ключей для корпоративных подсетей не нужно.

Если корпоративный конфиг пушит `redirect-gateway`, его `0.0.0.0/1` и `128.0.0.0/1` перебьют наш `/0` и весь не-RU трафик уйдёт в корпоративный туннель. В корпоративном профиле нужен `pull-filter ignore "redirect-gateway"`, проверяется в фазе 5.

### 1.7. Роуминг

`monitorDefaultRoutes()` (`defaultroutemonitor.go:64`) уже отслеживает смену физического default route и перепривязывает сокет. Туда же вешаем переустановку RU-маршрутов: удалить наши маршруты со старого интерфейса (помечаем их своим `Protocol`/метрикой, чтобы отличать от чужих), поставить на новый со свежим шлюзом. Пока идёт переустановка, RU-трафик идёт через VPN. Ожидание по времени: 6 000 `CreateIpForwardEntry2` это единицы секунд, замеряем в фазе 2, при необходимости ставим маршруты пачкой в отдельной горутине и логируем длительность.

Отключение Wi-Fi без нового интерфейса: маршруты остаются на неактивном интерфейсе, трафик падает в `/0`, при возврате той же сети шлюз мог смениться, поэтому переустанавливаем всегда по событию, а не по факту «интерфейс другой».

## 2. Список подсетей и обновление

### 2.1. Источник

По умолчанию ipverse (RIR-данные, агрегировано, ежедневно, есть v4 и v6, GitHub raw). URL v4 и v6 настраиваются, альтернативы: ipdeny, MetaCubeX geoip. Допустим локальный путь к файлу.

### 2.2. Хранение

`%ProgramFiles%\AmneziaWG\Data\geo\`:

```
ru-v4.list        # как скачали
ru-v6.list
meta.json         # { source_v4, source_v6, fetched_at, sha256_v4, sha256_v6, count_v4, count_v6, last_error }
settings.json     # update_on_start, stale_hours, min_prefix_v4, ipv6_mode, always_direct[], always_tunnel[], source_v4, source_v6
```

Каталог `Data` создаётся с ACL «только SYSTEM и Administrators» (`conf/path_windows.go:77`), обычный пользователь список подменить не может. В бинарник через `go:embed` кладётся снапшот (`geolist/data/ru-v4.txt`, `ru-v6.txt`, обновляется `go generate` перед релизом): первый запуск и работа без сети гарантированы.

### 2.3. Когда обновлять

1. `ManagerService.Start()` (`manager/ipc_server.go:89`), перед `InstallTunnel(path)`: если у туннеля `GeoSplit != ""`, включено «обновлять при старте» и `now - fetched_at > stale_hours` (по умолчанию 24), то синхронное обновление с таймаутом 15 с. Не получилось, стартуем на кэше, пишем в лог, `meta.last_error` и в трей.
2. Старт менеджер-сервиса (логон/загрузка): фоновая проверка через 30 с, результат применится при следующем старте туннеля.
3. Кнопка «Обновить сейчас» в UI.

Туннели, стартующие при загрузке как Windows-сервисы (`services/boot.go`), менеджера не ждут и читают кэш или встроенный снапшот.

### 2.4. Загрузка и проверка

Через существующий `updater/winhttp` (цепочка сертификатов проверяется Windows, системный прокси уважается). Сервис менеджера уже разрешён в WFP по пути exe (`permitWireGuardService`), скачивание работает и при поднятом kill-switch.

Файл принимается, только если: все строки парсятся как CIDR нужного семейства; `count_v4 ≥ 2000`, `count_v6 ≥ 200`; отклонение от предыдущего count не больше 50 %; размер < 4 МБ. Временный файл, `sha256`, атомарный `MoveFileEx`. Подписей у источников нет, записываем в `attacksurface.md`.

## 3. Гарантия «трафик не уходит напрямую»

Используется штатный kill-switch: пока запущен сервис туннеля, наружу разрешены только TUN, процесс туннеля, DHCP/NDP, DNS из конфига, RU-префиксы и серые адреса. Переподключение WireGuard не меняет адаптер и маршруты: пакеты в `/0` входят в wintun и без сессии молча отбрасываются `amneziawg-go`. Утечки нет.

Не покрыто и на этом этапе принято осознанно: падение процесса туннеля или остановка туннеля пользователем снимает фильтры вместе с адаптером, трафик идёт напрямую. Persistent-фильтры (lockdown) отложены, при необходимости добавляются позже отдельной фазой без изменения остального.

## 6. Матрица проверок

- RU-адрес (`77.88.8.8`) идёт напрямую: `tracert`, счётчики wintun не растут.
- Не-RU адрес идёт через туннель; при отсутствии handshake соединение висит, а не уходит напрямую (`Test-NetConnection`, `netsh wfp show state`).
- Число маршрутов и время установки в логе туннеля при порогах /24 и /22.
- Роуминг Wi-Fi → LTE → Wi-Fi: время переустановки RU-маршрутов, отсутствие «сирот» на старом интерфейсе (`route print` по нашему protocol id), RU и VPN-трафик ходят.
- Сон/пробуждение.
- Корпоративный OpenVPN параллельно: серые подсети и корпоративный DNS доступны, `redirect-gateway` отфильтрован.
- Домашняя сеть: принтер/NAS по серому адресу доступны при поднятом туннеле.
- IPv6: в режиме «только VPN» нет утечки через нативный v6.
- Устаревший список: подменить `fetched_at`, стартовать туннель, убедиться что скачалось; отключить сеть, стартовало на кэше; удалить кэш, стартовало на снапшоте.
- Список с мусором и список «в два раза короче» отвергаются.
- Убить `amneziawg.exe /tunnelservice`: трафик идёт напрямую, фиксируем как известное ограничение.

## 7. Риски и открытые вопросы

- **Время переустановки маршрутов при роуминге.** Если 6 000 маршрутов ставятся дольше 5 с, ставим их в горутине пачками и показываем в трее «переустановка маршрутов»; в это время RU идёт через VPN, не наружу.
- **Сироты-маршруты.** Маршруты помечаем собственным значением `Protocol` в `MIB_IPFORWARD_ROW2`, при старте и на роуминге вычищаем все с этой меткой, а не только «свои по памяти».
- **Число условий в одном WFP-фильтре.** Лимита в документации нет, начинаем с 256, проверяем `netsh wfp show filters` и время `fwpmFilterAdd0`.
- **Качество списка.** RIR-данные говорят о регистрации, не о географии. Anycast (Cloudflare, Google DNS) не RU и уйдёт через VPN, это правильно. GGC/YouTube-кэш внутри российских провайдеров уйдёт напрямую, при необходимости его префиксы вносятся в `always_tunnel`.
- **Обновление библиотеки upstream.** Правки в `amneziawg-windows` держим в 4–5 файлах за проверкой `GeoSplit != ""`, чтобы ребейз на новые теги Amnezia был дешёвым.
