# План: офисный split-tunnel и split-DNS в Windows-клиенте

Цель: при поднятом full-tunnel VPN сохранить доступ к корпоративным ресурсам в офисной сети — приватные подсети напрямую и резолв внутренних доменов через корпоративный DNS. Работает **независимо от GeoSplit** (geo-split может делаться на роутере, к которому подключается клиент, или не использоваться вовсе).

Сценарий пользователя (M.Видео, подтверждено 2026-10-27): офисный Wi-Fi, весь корпоратив в `10.0.0.0/8` и смежных сетях, доступны через обычный офисный шлюз (classless routes нет, таблица чистая). Внутренний суффикс `corp.mvideo.ru`, корпоративные DNS `10.95.0.8/.9/.10`, `10.170.18.8/.9`.

## Почему ломается (кратко)

1. **Маршруты**: `AllowedIPs = 0.0.0.0/0` ставит дефолт на wintun; подсеть самого адаптера работает (on-link специфичнее), остальные корпоративные подсети за офисным шлюзом уходят в туннель. hosts даёт IP, но маршрут к нему всё равно дефолт → туннель.
2. **DNS**: клиент вешает DNS туннеля на интерфейс, kill-switch (`firewall/blocker.go`, `blockDNS` allow 15 / deny 14) режет DNS ко всем прочим серверам. Внутреннее имя уходит на DNS туннеля → NXDOMAIN, а корпоративный DNS WFP-заблокирован.

## Ключи конфига (`[Interface]`, независимы от GeoSplit)

```
ExcludeRoutes = 10.0.0.0/8
SplitDNS = corp.mvideo.ru > 10.95.0.8, 10.95.0.9, 10.95.0.10
SplitDNS = intra.mvideo.ru > 10.170.18.8, 10.170.18.9
```

- `ExcludeRoutes` — список приватных префиксов/хостов через запятую: маршрут мимо туннеля + permit сквозь kill-switch.
- `SplitDNS` — повторяемый, одна строка на домен: `домен > сервер[, сервер...]`. NRPT-правило «этот суффикс резолвить на этих корпоративных серверах», остальное на DNS туннеля.

Движок маскировки активируется, если задан любой из `GeoSplit`, `ExcludeRoutes`, `SplitDNS`.

## Механизм

### Маршруты (переиспользуем движок geo-split)

- `loadGeoSplit` (tunnel/geosplit.go) строится и когда `GeoSplit` пуст, но заданы `ExcludeRoutes`/`SplitDNS`. В `direct4`/`direct6` досыпаются префиксы `ExcludeRoutes` (нормализованные) и `/32` каждого сервера `SplitDNS`.
- Существующий `createGeoRoute` ставит каждый префикс на физический интерфейс дефолта через его шлюз (маркер `RouteProtocolBbn`), переустанавливает при смене дефолта. `10.0.0.0/8` = один маршрут, дёшево.
- WFP-permit по префиксу (`permitRemotePrefixes`, вес 12) выпускает трафик мимо kill-switch.
- Офисный случай простой: classless routes нет, всё через дефолтный шлюз (проверено на машине пользователя).
- **Оговорка**: `ExcludeRoutes` не должен пересекаться с адресом туннеля и теми `AllowedIPs`, что реально нужны в туннеле. Туннель M.Видео — `172.16/12`, поэтому `10/8` безопасен.

### Split-DNS (новое)

- При подъёме туннеля для каждой строки `SplitDNS` регистрируем NRPT-правило (namespace = суффикс, nameservers = серверы) в локальном NRPT-сторе (`Dnscache\Parameters\DnsPolicyConfig`, тот же, куда пишет `Add-DnsClientNrptRule`). Имена под доменом → корпоративный DNS, остальное → DNS туннеля. При отключении — удаляем. Жизненный цикл привязан к состоянию туннеля, как у маршрутов.
- **Permit корпоративного DNS**: IP серверов `SplitDNS` добавляются в список разрешённых DNS, передаваемый в `EnableFirewall` (addressconfig.go:197, сейчас туда идёт только `conf.Interface.DNS`). Это даёт им DNS-allow веса 15, выше DNS-deny веса 14. Без этого запрос к корпоративному DNS блокируется даже при наличии маршрута.
- Текущий клиент NRPT не использует вообще (`luid.SetDNS` ставит только DNS интерфейса и search-list). Точный способ записи NRPT (прямые записи в реестр против DNS policy API) и необходимость уведомления Dnscache — уточнить при реализации.

## Правки по файлам (awg-lib + awg-client)

- `conf/config.go`: поля `ExcludeRoutes []netip.Prefix`, `SplitDNS []SplitDNSRule{Domain string; Servers []net.IP}`.
- `conf/parser.go`: кейсы `excluderoutes`, `splitdns` (повторяемый); `conf/writer.go`: вывод обоих. Хелперы разбора рядом с `geosplit.go`. Round-trip тесты.
- `tunnel/geosplit.go`: активация на новых ключах, засев direct-набора, хранение правил split-DNS.
- `tunnel/addressconfig.go`: серверы split-DNS в permit `EnableFirewall`; регистрация/снятие NRPT вокруг подъёма/спуска.
- `tunnel/` новый файл NRPT: register/remove правил.
- `awg-client` UI (позже): поля в редакторе туннеля, подсветка ключей в `ui/syntax`, русские строки.

## Фазы

1. Парсер + поля + writer + round-trip тесты (без поведения).
2. Маршруты: засев direct-набора из `ExcludeRoutes`, активация движка без `GeoSplit`. Тест исключения `10/8` на full-tunnel конфиге.
3. Split-DNS: NRPT register/remove + permit DNS. Тест: `corp.mvideo.ru` резолвится через `10.95.0.8` при поднятом туннеле, внешний DNS — через туннель.
4. UI + строки.
5. Боевой тест в офисе: сборка MSI (с согласия), проверка — внутренние домены резолвятся, `10.x` доступна, интернет в туннеле, kill-switch по-прежнему без утечек.

## Открытые вопросы

- Точный механизм NRPT и обновление кэша Dnscache.
- IPv6 внутри не нужен (корпоратив IPv4 `10/8`), split-DNS/маршруты только v4.
- На машине также есть Cisco AnyConnect (DNS `10.95.0.8/.9` ранее виделись как pushed им). Этот офисный сценарий — когда AnyConnect НЕ поднят, а пользователь на офисном Wi-Fi. Если AnyConnect активен, он сам ставит свои маршруты/DNS; конфликтов с нашими исключениями быть не должно (та же приватная сеть), но проверить в фазе 5.
